# UDP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A UDP service in the cluster is reachable through an edge: the operator accepts `UDP` listeners and `UDPRoute`s, the edge opens the UDP port, and each visitor packet travels through the iroh tunnel as QUIC datagrams to a backend Service and back.

**Architecture:** UDP never touches HAProxy. The edge keeps a flow per (port, visitor address), numbers it, and sends each packet as one or more QUIC datagrams with an 18-byte header; the operator keeps one connected UDP socket per flow towards a backend it picked by weight, and sends replies back under the same flow id. Packets larger than one QUIC datagram are split and reassembled at the far end. The controller pipeline of steps 2 and 3 stays: the model gains UDP listeners and `UDPRoute`, the render adds a table of UDP targets to each edge plan, and the engine hands that table to the link.

**Tech Stack:** Rust 2024 (1.100), tokio, iroh 1.5 (`Connection::send_datagram`, `read_datagram`, `max_datagram_size`), kube 5.1, gateway-api 0.23 (`gateway_api::udproutes::v1::UdpRoute`, Gateway API v1.7.0 standard channel). New dependencies: `bytes` 1 (already in the tree through iroh), `proptest` 1 (dev, `proto` only).

**Spec:** `docs/superpowers/specs/2026-11-23-iroh-gateway-design.md`, section "Tunnel protocol", paragraph "UDP", and every other mention of UDP. This plan implements build step 4 of 5. The Helm chart, metrics and release packaging are step 5.

## Global Constraints

- Rust edition 2024, `rust-version = "1.100"`. Run every cargo command through the flake: `nix develop -c cargo …`.
- Work on the branch `udp`, not on `main`. Never push.
- ALPN stays `iroh-gateway/0`. An edge of the previous version answers a `udp` listener with a bind error, and a previous operator never asks for one, so old and new binaries keep working together. No existing wire format changes: the golden bytes in `proto/src/control.rs` stay as they are.
- Datagram header, 18 bytes, big-endian, in both directions: `listener id u32 | flow id u64 | packet id u32 | fragment index u8 | fragment count u8`, then the payload.
- Constants, all in `proto/src/datagram.rs`: `HEADER_LEN = 18`, `MAX_PACKET = 65_535`, `MAX_FRAGMENTS = 64`, `REASSEMBLY_WINDOW = 1 s`, `REASSEMBLY_BYTES = 4 MiB`, `UDP_FLOW_IDLE = 60 s`, `MAX_UDP_FLOWS = 4096`.
- Delivery is unreliable and unordered, as UDP is. Nothing waits, retries or blocks for a UDP packet: sends use `Connection::send_datagram` (never `send_datagram_wait`), sockets use `try_send`/`try_send_to` or a bounded queue with `try_send`, and whatever does not fit is dropped.
- `max_datagram_size()` is read for every packet sent, because it changes with the path. `None` or a size of `HEADER_LEN` or less drops the packet.
- **Flow tables are bounded and evict.** At the cap a new flow replaces the least recently used one. A flow is forgotten after `UDP_FLOW_IDLE` without a packet in either direction. (This departs from the design's "refuses new ones beyond it": with refusal, about 70 spoofed packets a second would keep every new visitor out. Task 7 amends the design.)
- **A flow never outlives what it was made for.** The edge forgets every flow when the session changes and the flows of a port when the port closes. The operator drops a flow when its listener id leaves the routes or its backend leaves the listener's targets. A reply for an unknown flow is dropped.
- **Nothing a peer sends can hurt the receiver.** A datagram that is short, has `count == 0`, `count > MAX_FRAGMENTS`, `index >= count`, or belongs to a packet above `MAX_PACKET` is dropped; reassembly never holds more than `REASSEMBLY_BYTES`; no datagram ends a session or panics a task. On the operator, a datagram whose listener id is not a UDP listener of the current `Config` is dropped, and a known flow id arriving under another listener id is dropped.
- The visitor's address is not passed to the backend (a design non-goal). The backend sees the operator pod.
- UDP does not depend on HAProxy: a UDP listener adds nothing to `haproxy.cfg`, and the UDP targets of a running link follow every render at once, whether or not HAProxy takes that render's configuration. The order "table first, then ask the edge for the port" holds, so an edge never opens a UDP port that has nothing behind it.
- `TCP`-family listeners (`TCP`, `HTTP`, `HTTPS`) and a `UDP` listener may use the same port number on one Gateway. Two `UDP` listeners on one port conflict.
- Carried over and still binding: nothing is applied before every watch store has listed once; the render is byte-for-byte stable for equal models; an unusable route affects no other route, listener or Gateway; text from an edge is cut by `truncate_status_text` before it reaches a status.
- Tests that need `haproxy` find it on `PATH`. Tests that need an API server are `#[ignore = "needs KUBEBUILDER_ASSETS"]`.
- All non-ignored tests pass on macOS and Linux, on loopback only, with pristine output, and leave no process, port or file behind. Free ports come in random order on Linux: a test never assumes an order among ports it obtained. **macOS refuses UDP packets above 9,216 bytes on loopback by default**: tests that run everywhere use at most 9,000 bytes; tests with larger packets are `#[cfg(target_os = "linux")]`.
- A test that waits for a UDP packet uses a timeout and, where a packet may legitimately be lost (anything through a real QUIC connection), sends again until the answer arrives or `STEP` (10 s) passes. A test that asserts "nothing arrives" waits 300 ms.
- `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings` are clean at every commit. No new `unsafe`.
- Build output stays under `target/`. Run `chmod -R u+w target/envtest 2>/dev/null; nix develop -c cargo clean` when the last task is done.

## Review Focus

Conditions the spec implies that are most likely to bite a real user. Each has a test in the task named.

1. Someone floods a UDP port with packets from made-up source addresses. New visitors must still get a flow, and memory must stay bounded on both sides. (Task 1, `at_capacity_the_least_recently_used_entry_is_replaced`; Task 2, `at_the_flow_cap_the_least_recently_used_flow_is_replaced`; Task 3, `flow_cap_replaces_the_least_recently_used`)
2. A packet does not fit one QUIC datagram: a 1,400-byte game or VPN packet on a fresh path, an EDNS answer, a 9,000-byte packet. It must arrive whole or not at all, never truncated or mixed with another packet. (Task 1, the properties; Task 3, `large_packets_echo_through_edge_and_operator`)
3. The `UDPRoute` changes backend or is deleted while visitors are sending. No packet may reach the old backend afterwards, and no reply from it may reach a visitor. (Task 3, `flow_ends_when_its_backend_leaves_the_targets`; Task 5, `removed_udp_listener_stops_forwarding`)
4. The operator reconnects or is replaced while flows exist. A reply must never reach a visitor of an earlier session's flow with the same number. (Task 2, `flows_restart_with_a_new_session`)
5. DNS: one Gateway with `TCP` 53 and `UDP` 53. Both must be accepted, bound on the edge and forwarded to their own routes. (Task 2, `tcp_and_udp_listeners_share_a_port_number`; Task 4, `tcp_and_udp_listeners_share_a_port`; Task 6, `udp_and_tcp_listeners_on_one_port_are_both_programmed`)
6. A broken or hostile edge sends garbage datagrams. The operator must keep serving every other flow and edge. (Task 1, `arbitrary_datagrams_never_panic_or_exceed_the_budget`; Task 3, `malformed_datagrams_do_not_end_the_session`)

## Not in this plan

- The visitor's address towards UDP backends (PROXY protocol for UDP), per-pod balancing, health checks of UDP backends.
- HTTP/3. HAProxy keeps serving HTTP over TCP only.
- Replying from the address the visitor sent to on an edge with several public addresses of one family (it needs `IP_PKTINFO`). Replies leave from the address the edge's routing picks.
- A share of the tunnel reserved for TCP. QUIC sends datagrams ahead of stream data, so a UDP flood that fills the tunnel slows TCP and HTTP through the same edge. This plan gives the edge an optional rate limit for UDP (`--udp-rate-limit`), off by default, and documents the risk.
- Batched socket I/O (`recvmmsg`, GSO) and `read_many_datagrams`.
- Metrics, the Helm chart: step 5.

// datagram.rs
pub const HEADER_LEN: usize = 18;
pub const MAX_PACKET: usize = 65_535;
pub const MAX_FRAGMENTS: usize = 64;
pub const REASSEMBLY_WINDOW: Duration = Duration::from_secs(1);
pub const REASSEMBLY_BYTES: usize = 4 * 1024 * 1024;
pub const UDP_FLOW_IDLE: Duration = Duration::from_secs(60);
pub const MAX_UDP_FLOWS: usize = 4096;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Header { pub listener_id: u32, pub flow_id: u64, pub packet_id: u32, pub index: u8, pub count: u8 }

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum DatagramError { #[error("datagram shorter than its header")] Short, #[error("invalid fragment numbers")] BadFragment }

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum SplitError { #[error("packet too large to send")] TooLarge, #[error("no room for a payload")] NoRoom }

impl Header {
    pub fn encode(&self) -> [u8; HEADER_LEN];
    /// The header and the payload after it. `BadFragment` for count 0, count > MAX_FRAGMENTS, index >= count.
    pub fn decode(datagram: Bytes) -> Result<(Header, Bytes), DatagramError>;
}

/// The datagrams that carry `payload`, each at most `max_datagram` bytes, in fragment order.
pub fn split(listener_id: u32, flow_id: u64, packet_id: u32, payload: &[u8], max_datagram: usize)
    -> Result<Vec<Bytes>, SplitError>;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Packet { pub listener_id: u32, pub flow_id: u64, pub payload: Bytes }

pub struct Reassembler { /* private */ }
impl Reassembler {
    pub fn new(max_bytes: usize, window: Duration) -> Self;
    /// Takes one decoded datagram; the whole packet once its last missing fragment arrives.
    pub fn push(&mut self, header: Header, payload: Bytes, now: Instant) -> Option<Packet>;
    /// Payload bytes held for incomplete packets.
    pub fn buffered(&self) -> usize;
    pub fn clear(&mut self);
}

// idle.rs
pub struct IdleMap<K, V> { /* private */ }
impl<K: Hash + Eq + Clone, V> IdleMap<K, V> {
    /// Panics if `capacity` is 0.
    pub fn new(capacity: usize, idle: Duration) -> Self;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    /// Without marking it used.
    pub fn get(&self, key: &K) -> Option<&V>;
    /// Marks the entry used at `now`.
    pub fn touch(&mut self, key: &K, now: Instant) -> Option<&mut V>;
    /// Inserts as used at `now`. Returns what it pushed out: the entry that had this key, or, when
    /// the map was full, the least recently used one.
    pub fn insert(&mut self, key: K, value: V, now: Instant) -> Option<(K, V)>;
    pub fn remove(&mut self, key: &K) -> Option<V>;
    /// Removes and returns the entries `keep` refuses.
    pub fn retain(&mut self, keep: impl FnMut(&K, &V) -> bool) -> Vec<(K, V)>;
    /// Removes and returns every entry not used for `idle` or longer at `now`.
    pub fn expire(&mut self, now: Instant) -> Vec<(K, V)>;
    /// When the least recently used entry becomes idle.
    pub fn next_expiry(&self) -> Option<Instant>;
    pub fn clear(&mut self);
}

// transport.rs
pub const DATAGRAM_SEND_BUFFER: usize = 256 * 1024;
pub const DATAGRAM_RECEIVE_BUFFER: usize = 1024 * 1024;
```

`Instant` is `std::time::Instant` in both files, so the types are plain data structures; callers on tokio pass `tokio::time::Instant::now().into_std()`.

Rules the signatures do not say:

- `split`: `NoRoom` when `max_datagram <= HEADER_LEN`; `TooLarge` when `payload.len() > MAX_PACKET` or more than `MAX_FRAGMENTS` fragments would be needed. An empty payload gives one datagram of `HEADER_LEN` bytes with `count == 1` (UDP allows empty packets). Every fragment but the last carries exactly `max_datagram - HEADER_LEN` payload bytes.
- `Reassembler::push`: `count == 1` returns the packet at once and stores nothing. Otherwise packets are keyed by `(flow_id, packet_id)`. Before storing: entries first seen `window` or longer ago are dropped. A fragment whose `count` or `listener_id` differs from its entry's drops the entry and the fragment. A repeated index is ignored. An entry whose payload would exceed `MAX_PACKET` is dropped. When storing would take `buffered()` above `max_bytes`, the oldest entries are dropped until it fits; a fragment larger than `max_bytes` is dropped. The completed payload is the fragments in index order.
- `IdleMap`: recency is by the `now` given to `touch` and `insert`; ties go to the entry touched first. `expire` and `next_expiry` must not scan the whole map on every call (keep an order index).
- `transport_config` sets `datagram_send_buffer_size(DATAGRAM_SEND_BUFFER)` and `datagram_receive_buffer_size(Some(DATAGRAM_RECEIVE_BUFFER))` for both roles.

CLI: `--max-udp-flows <N>` (env `IROH_GATEWAY_EDGE_MAX_UDP_FLOWS`, default 4096, range `1..=4096`); `--udp-rate-limit <BYTES_PER_SECOND>` (env `IROH_GATEWAY_EDGE_UDP_RATE_LIMIT`, optional, at least 1). `udp_flow_idle` has no flag and is `UDP_FLOW_IDLE`.

Behaviour:

- `ListenerSet::apply` binds a `udp` listener with `tokio::net::UdpSocket::bind((bind_ip, port))` and reports `Bound` or the error, exactly as for TCP. The `Bound` entry (id atomic and task) is the same. Closing a UDP port aborts and awaits its task, which owns the socket, then calls `forget_port`; the port is free when `apply` or `close_all` returns. `bound()` sorts by `(port, protocol == Udp)`.
- One task per UDP port owns the socket and nothing else holds it. It receives into one 65,535-byte buffer and hands each packet to the hub with the listener's current id (read from the atomic per packet), the visitor's address exactly as received (not made canonical: it is only ever used to send the reply from the same socket), and the sender of the port's reply queue. It sends what arrives on the reply queue (bounded, 256 packets) with `send_to`; a send error is logged at debug through a `LogThrottle` and otherwise ignored. A receive error is treated the same and the task goes on.
- The hub, per visitor packet: no session → drop. Over the rate limit → drop. Find or make the flow for `(port, visitor)`; a new flow takes the next flow id (a `u64` counted from 1 for the life of the hub, never reused) and, at the cap, replaces the least recently used flow. Split with the flow's next packet id (a wrapping `u32` per flow) and `conn.max_datagram_size()`, and `send_datagram` each fragment; any error drops the rest of the packet.
- The hub, per session: `set_session(Some(conn))` starts a task that reads datagrams from `conn` until it closes, and a new `set_session` aborts it. For each datagram: decode, reassemble (`Reassembler::new(REASSEMBLY_BYTES, REASSEMBLY_WINDOW)`, cleared with the flows), look the flow id up, check the header's listener id is the one the flow's last visitor packet was sent under, mark the flow used, and `try_send` `(visitor, payload)` to the port's reply queue. A full queue drops the packet; a closed queue removes the flow. The same task expires idle flows, at the latest one second after they become idle.
- Rate limit: a token bucket of `rate` bytes per second holding at most `max(rate, MAX_PACKET)` bytes, charged with the payload length; a packet that does not fit is dropped whole.
- The supervisor (`edge/src/lib.rs`): `set_session(None)` when a session is installed, replaced, ended or at shutdown; `set_session(Some(conn))` in `apply`, after `listeners.apply`, the first time that session is configured. So no UDP packet is forwarded on a session before its first `Config`, as for TCP. `Session` gets `pub fn conn(&self) -> &Connection`.
- Dropped packets are counted in the hub (`AtomicU64` per reason: no session, rate limit, send error, unknown flow, bad datagram) for step 5's metrics, and logged at debug through a `LogThrottle`; nothing is logged per packet.

// operator/src/tunnel/udp.rs, re-exported from operator::tunnel
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct UdpTarget { pub addr: SocketAddr, pub weight: u32 }
/// Where the packets of each UDP listener go. Keys have `Protocol::Udp`.
pub type UdpTargets = HashMap<ListenerKey, Vec<UdpTarget>>;
/// The target `roll` falls on when the weights are laid end to end; `roll` is taken modulo the
/// sum of the weights. None when no target has a weight above 0.
pub fn pick(targets: &[UdpTarget], roll: u64) -> Option<SocketAddr>;

// operator/src/tunnel/link.rs
pub struct LinkOptions {
    /* existing fields */
    pub udp_max_flows: usize,     // MAX_UDP_FLOWS
    pub udp_flow_idle: Duration,  // UDP_FLOW_IDLE
}
impl EdgeLink {
    pub fn spawn<C: Connector>(
        endpoint: Endpoint, opts: LinkOptions,
        desired: watch::Receiver<Vec<ListenerKey>>, connector: Arc<C>,
        udp: watch::Receiver<UdpTargets>,
    ) -> LinkHandle;
}
```

Behaviour of the forwarder, one per session, started when the session starts and aborted with it:

- For each datagram of the connection: decode; the listener id must be in the session's routes and its key must be `Protocol::Udp`; reassemble (`Reassembler::new(REASSEMBLY_BYTES, REASSEMBLY_WINDOW)`); then by flow id:
  - a known flow under the same listener id: `try_send` the payload on its socket and mark it used;
  - a known flow under another listener id: drop;
  - an unknown flow: `pick` among the listener's targets with `fastrand::u64(..)`; none → drop. Bind a UDP socket on the unspecified address of the target's family, port 0, `connect` it to the target, insert the flow (at `udp_max_flows` the least recently used flow is replaced and its task aborted), send the payload.
- Each flow has a task that waits for its socket to be readable, receives into a 65,535-byte buffer shared by all flows of the session (a `std::sync::Mutex`, held only for the non-blocking `try_recv` and the split), marks the flow used, and sends the reply under the flow's listener id and flow id with a wrapping per-flow packet id. A receive or send error on the socket (a backend that is not listening answers with ICMP, which surfaces as `ConnectionRefused`) is ignored and the task goes on.
- When the targets change: flows whose target is no longer listed for their listener are dropped. When the routes change: flows whose listener id is gone are dropped. Idle flows are dropped at the latest one second after `udp_flow_idle`. A dropped flow's task is aborted and its socket closed.
- A closed `udp` or routes channel keeps its last value; it does not end the forwarder.
- Dropped packets are counted per reason in the forwarder (for step 5) and logged at debug through a `LogThrottle`; a datagram for a listener id not in the routes is logged at warn through its own throttle, as an edge that sends those is broken.

Static mode: `run_static` gives each `udp` listener of the file to the link as one `UdpTarget { addr: target, weight: 1 }` and each `tcp` listener to the `StaticConnector`, as now. The file format does not change.

In `engine.rs` this task only makes the code compile: each `Running` holds a `watch::Sender<UdpTargets>` created with an empty table. Task 5 fills it.
